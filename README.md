# مِداد — منصة المحاضرات الجامعية

## مكوّنات المشروع

- `artifacts/lecture-platform`: واجهة React وVite للطلاب وهيئة التدريس.
- `artifacts/api-server`: واجهة Express، ومصادقة Clerk، وواجهات المحاضرات والواجبات والوسائط.
- `lib/api-spec/openapi.yaml`: المصدر الوحيد لعقود API.
- `lib/api-client-react` و`lib/api-zod`: عميل React Query ومخططات التحقق المولّدة.
- `lib/db/src/schema`: مخططات Drizzle وقاعدة البيانات.

## التطوير المحلي

من جذر مساحة العمل:

```powershell
pnpm install --frozen-lockfile
pnpm --filter @workspace/api-spec codegen
pnpm run typecheck
```

يلزم إعداد `DATABASE_URL` و`VITE_CLERK_PUBLISHABLE_KEY` و`CLERK_PUBLISHABLE_KEY` و`CLERK_SECRET_KEY` قبل تشغيل الخدمات المعتمدة عليها. بعد تغييرات مخطط قاعدة البيانات، طبّق المخطط على قاعدة البيانات المقصودة باستخدام:

```powershell
pnpm --filter @workspace/db push
```

لا تشغّل هذا الأمر على قاعدة إنتاج قبل مراجعة تغييرات المخطط ونسخة احتياطية حديثة.

تُحمّل خدمة API متغيرات التطوير المحلية من `lib/db/.env`. أضف `GEMINI_API_KEY` هناك لاستخدام دالة Gemini الخادمية؛ لا تستخدم هذا المفتاح في متغيرات `VITE_` أو في الواجهة الأمامية.

شغّل كل خدمة في نافذة طرفية منفصلة:

**نافذة الخادم:**
```powershell
pnpm --filter @workspace/api-server dev
```

**نافذة الواجهة:**
```powershell
pnpm --filter @workspace/lecture-platform dev
```

تقرأ الواجهة مفتاح Clerk العام ذي البادئة `VITE_` من `lib/db/.env`، بينما تبقى المفاتيح السرية على الخادم. عند عدم تسجيل الدخول، يفتح المسار `/` صفحة Clerk على `/sign-in`؛ وتبقى الصفحة التعريفية متاحة على `/welcome`. يمكن ضبط `API_SERVER_URL` لتوجيه وسيط Vite إلى خادم API يعمل على منفذ مختلف؛ الافتراضي `http://127.0.0.1:3000`.

## النشر على Vercel

إعداد `vercel.json` يبني مساحة العمل، وينشر ملفات واجهة Vite الثابتة، ويحوّل الطلبات إلى `/api/*` إلى خادم Express عبر وظيفة Node، مع إبقاء المسارات الداخلية للواجهة صالحة عند فتحها مباشرة. اربط المستودع من جذره واترك أمر التثبيت والبناء المحددين في الملف.

أضف المتغيرات التالية في إعدادات مشروع Vercel لكل بيئة مطلوبة (Production وPreview):

- `VITE_CLERK_PUBLISHABLE_KEY`: مفتاح Clerk العام لواجهة Vite.
- `CLERK_SECRET_KEY`: المفتاح السري لخادم Clerk؛ مطلوب في الإنتاج.
- `DATABASE_URL`: اتصال قاعدة بيانات PostgreSQL.
- `APP_ORIGIN`: أصل الموقع المنشور، مثل `https://midad.example.com`، إذا اختلف عن الأصل الذي يراه الخادم.
- `GOOGLE_CLOUD_PROJECT` و`PRIVATE_OBJECT_DIR` و`PUBLIC_OBJECT_SEARCH_PATHS` و`GOOGLE_APPLICATION_CREDENTIALS_JSON` (JSON حساب خدمة Google Cloud بصلاحية محدودة للمخزن) لتخزين ملفات المحاضرات.

يستخدم Clerk تلقائياً مسار الوكيل `/api/__clerk` في الإنتاج؛ يمكن تخصيصه عبر `VITE_CLERK_PROXY_URL`. لا تضع `CLERK_SECRET_KEY` أو بيانات اعتماد Google Cloud في متغيرات `VITE_` أو في ملفات متتبعة. لا يكتمل تشغيل ميزات قاعدة البيانات والوسائط حتى تُضبط الخدمات الخارجية ومتغيراتها في Vercel.

## الأدوار والصلاحيات

يُحسم الدور من `publicMetadata.role` في Clerk على الخادم، وليس من قيمة يرسلها المتصفح:

- `student` أو حساب مسجل بلا دور هيئة تدريس: مشاهدة المحتوى المنشور وتسليم الواجبات.
- `instructor`: إدارة محاضراته وواجباته فقط، والاطلاع على تسليماتها ونشاط طلاب محتواه.
- `admin`: إدارة محتوى جميع الأساتذة، وتعديل بيانات المقرر، ومسح سجل الحضور.

يجب منح الأدوار من Clerk عبر واجهة إدارية موثوقة. لا تمنح دور `admin` من واجهة المستخدم أو من `unsafeMetadata`. الأداة `scripts/grant-lecture-admin.mjs` تمنح مديراً لحساب بريده الإلكتروني موثّق، وتتطلب `CLERK_SECRET_KEY`.

يسمح إعداد الحساب الذاتي باختيار دور `student` فقط؛ يجب أن يمنح مدير موثوق أدوار `instructor` و`admin` في `publicMetadata.role`. بعد تسجيل الدخول، يُوجّه كل دور إلى `/student` أو `/instructor` أو `/admin` على الترتيب. مسارا `/instructor` و`/dashboard/instructor` محميان للأستاذ والمدير.

تُقبل إجابة واجب واحدة لكل طالب. يمكن التسليم بعد الموعد، لكن تُعلّم المحاولة بوضوح على أنها متأخرة في لوحة الأستاذ.

تتحقق واجهات الطلاب من دور `student` (أو من حساب مسجل لم يُعيّن له دور بعد)، بينما تتطلب واجهات المحتوى دور `instructor` أو `admin` وتقيّد وصول الأستاذ بمحتواه. لا يكفي إخفاء روابط الواجهة؛ الخادم هو مصدر القرار النهائي. وضع المصادقة التجريبية المحلي محصور في التطوير ومُعطّل للكتابة.

تستخدم الواجهة جلسات Clerk وطلبات same-origin؛ لا تحفظ رموز الجلسات في `localStorage`. تتحقق خدمة API من `Origin` في كل طلب يغيّر البيانات وتمنع الطلبات العابرة للمواقع. انشر الواجهة وAPI على أصل واحد خلف reverse proxy. إذا كان المضيف الذي يراه الخادم يختلف عن أصل الواجهة العام، اضبط `APP_ORIGIN` على أصل الواجهة الكامل، ويمكن إدراج عدة أصول مفصولة بفواصل؛ لا يُعد هذا الإعداد بديلاً عن إعداد CORS والكوكيز الآمنة عند تصميم نشر cross-origin.

تُكتب أحداث التدريس والإدارة في جدول `audit_logs` ضمن معاملة قاعدة البيانات نفسها، وتشمل إنشاء/تعديل/أرشفة المحاضرات والواجبات، وتغيير بيانات المقرر، ومسح الحضور، وإجراءات أعضاء هيئة التدريس في التفاعل. لا تسجل الأحداث نصوص الإجابات أو محتوى المستخدم. بعد إضافة الجدول، طبّق مخطط Drizzle على قاعدة التطوير المقصودة قبل تشغيل الخدمة.

تحتوي لوحة التدريس على روابط جانبية ومسار تنقل وبحث سريع عبر `Ctrl+K` أو `⌘K`. يبحث البحث في بيانات المقرر والمحاضرات وأسئلة الاختبارات والواجبات التي يملك المستخدم صلاحية الوصول إليها. يحفظ تقدم مشاهدة الفيديو في قاعدة البيانات لكل طالب ومحاضرة ويستأنف من آخر موضع. صفحات 403 و404 و500 منفصلة، وتستخدم اللوحات مؤشرات تحميل أثناء جلب البيانات.

تتيح مساحة التفاعل للأستاذ إنشاء فترات أسبوعية مدتها 10 أو 15 دقيقة، ومراجعة أسئلة الطلاب والحجوزات وروابط غرف اللقاء الخاصة. تعرض واجهة الطالب المواعيد غير المحجوزة للتاريخ المحدد فقط. يمكن للأستاذ إرفاق رابط HTTPS من Zoom أو Google Meet بكل حجز. تشمل مؤشرات لوحة التدريس سجلات المشاهدة والتعليقات المرتبطة بتوقيت المحاضرة وإجابات الاختبارات، وتُقيّد بيانات الأستاذ بمحاضراته. بعد تغييرات مخطط Drizzle، طبّق المخطط على قاعدة التطوير المقصودة قبل تشغيل الخدمة.

لا توجد حالياً واجهات لإدارة حسابات Clerk أو لتعديل درجات يدوياً؛ تمنح الأدوار عبر أدوات الإدارة الموثوقة، وتُسجل محاولات الاختبارات تلقائياً. أضف واجهات خاصة لهذه العمليات قبل توسيع نطاق سجل التدقيق إليها.

## تخزين ملفات المحاضرات

رفع الفيديو وPDF يستخدم روابط PUT موقّعة قصيرة العمر إلى Google Cloud Storage؛ لا تمر الملفات الكبيرة عبر خادم API. إعداد الخادم:

- `PRIVATE_OBJECT_DIR`: مسار خاص بصيغة `/bucket-name/prefix`.
- `GOOGLE_CLOUD_PROJECT`: معرّف مشروع Google Cloud.
- بيانات اعتماد خدمة Google Cloud عبر Application Default Credentials.

اضبط CORS على الحاوية للسماح بـ `PUT` و`Content-Type` من أصل الموقع المنشور؛ وإلا سيمنع المتصفح الرفع المباشر. لا تجعل الحاوية عامة. الملفات تبقى خاصة، ويصدر الخادم رابط قراءة قصير العمر بعد التحقق من تسجيل الدخول وارتباط الملف بمحاضرة منشورة. الحد الأعلى للفيديو 2 GiB ولـPDF هو 25 MiB، مع التحقق من نوع المحتوى على الخادم قبل حفظ مرجع الملف.
